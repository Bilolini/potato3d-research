Use only the archived unchanged RGB-D frame 2R1-10 / 364, the released camera intrinsics and the existing annotation. Run the official TripoSR weights twice on CPU. No color edits or cohort scoring.

Use the release alpha mask and the upstream foreground crop, 0.85 padding ratio, neutral gray alpha composite and 512-pixel model resize. Skip learned background removal in both passes so the silhouette stays fixed. Transport the pin box through the same crop and resize, count model pixels with pin support and save the actual model RGB before ImageNet normalization. Preserve the released density threshold of 25. Use a frozen 128³ grid and the CPU scikit-image marching-cubes implementation with the same density field and axes.

TripoSR takes RGB alone and exports in normalized coordinates. Before considering it a metric comparison, fit one fixed uniform similarity to the first unchanged result using only the released foreground mask, depth, and intrinsics. Use the author's preview camera at azimuth and elevation zero, mapping model coordinates to camera axes as (y, −z, −x). Estimate each lateral scale from the ratio of the observed back-projected and predicted silhouette spans (2nd–98th percentiles). Sample the predicted silhouette as an orthographic grid of rays. Use the geometric mean of the two scale estimates, align lateral span midpoints, and align the near-surface depth percentiles. Reproject into the measured calibrated perspective camera. Require lateral scale estimates within a factor of 1.25, silhouette IoU of at least 0.75, and median absolute visible depth residual of at most 10 mm. Use a fixed checkerboard half of valid observed pixels for fitting and the other half for the depth check. These are feasibility thresholds for an approximate observation-anchored scale, with no claim of reconstruction accuracy. Never refit pose or scale per prediction if using this adapter for paired conditions.
